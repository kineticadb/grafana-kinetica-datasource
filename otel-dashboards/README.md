# OpenTelemetry exporter dashboards

Grafana dashboards for the metrics the
[Kinetica OpenTelemetry Collector exporter](https://github.com/kineticadb/otel-exporter) writes to
Kinetica. They are kept here, with their tests, to test the exporter's metric tables and this plugin
together.

**They are not part of the plugin.** The plugin package holds only the build of `src/` and the
backend, so these dashboards are not installed with it, and the plugin does not need them.

## Requirements

The dashboards work only with the latest exporter and the updated plugin:

| | Version |
|--|--|
| Kinetica OpenTelemetry exporter | The latest, which writes metrics to a series table, `metric_series`, with its labels in a `JSON(text_search)` column, and to narrow point tables, `metric_number_point`, `metric_histogram_point` and so on. Until it is released, that is branch `feature/otel_json_persistence` of `kineticadb/otel-exporter`. Earlier exporters wrote metrics to other tables, which the dashboards cannot read. |
| Kinetica datasource plugin (`kinetica-grafana-datasource`) | 1.1.0 or later. The dashboards use its label macros, its *Format as: Time series* and its detection of time columns by type, none of which 1.0.12 and earlier have. |
| Grafana | 12.3.0 or later |
| Kinetica | Full-text search enabled (`enable_text_search = true`), which the exporter's metric tables need |

Each dashboard lists the plugin and Grafana versions in `__requires`, so Grafana warns when you
import it with an older one.

## Dashboards

| File | Title | What it shows |
|--|--|--|
| `dashboards/otel-metrics-http.json` | OTel metrics on Kinetica / HTTP services | Requests, 5xx responses, error ratio, mean duration and active requests per service, the busiest routes and the slowest exemplars, from the HTTP server metrics of the OpenTelemetry semantic conventions (`http.server.request.duration`, `http.server.active_requests`) |
| `dashboards/otel-metrics-hosts.json` | OTel metrics on Kinetica / Hosts | CPU utilization, load average, memory, filesystem utilization, and network and disk throughput per host, from the collector's `hostmetrics` receiver |
| `dashboards/otel-metrics-inventory.json` | OTel metrics on Kinetica / Inventory | The metrics, series, services and label keys in the metric tables, the points written and the new series |

They use these features of the plugin:

- **Variables.** *Schema* is the schema the exporter writes to (default `otel`). *Service*, *Route*
  (HTTP dashboard) and *Host* (hosts dashboard) are multi-value variables read from
  `metric_series`, each filtered by the ones before it. Their *All* value is `*`, which filters
  nothing.
- **Label filters.** Each panel filters the series it reads with
  `$__labelMatch(labels, 'service.name', ${service:json})` and the like, which the plugin expands to
  one `text_match` call on the series' labels.
- **Time.** `$__timeFilter` limits each query to the dashboard's time range, and
  `$__timeGroup(time_unix, $__interval) AS time` buckets it by the zoom level, a minute at least
  (each panel's *Min interval*).
- **Series.** Time series panels use *Format as: Time series*, which makes one series per service,
  host or other text column the query returns.

Rates assume cumulative temporality, the default of most SDKs; for delta, run the collector's
`deltatocumulative` processor. *Active requests* is filtered by service only:
`http.server.active_requests` carries no route.

## Using them

Import a dashboard (*Dashboards > New > Import*) and pick a Kinetica datasource for it, or provision
them: copy `dashboards/` to `/var/lib/grafana/dashboards/kinetica-otel` and `provisioning.yml` to
Grafana's `provisioning/dashboards` directory. Provisioned dashboards use the default Kinetica
datasource. Then set *Schema* to the schema in the exporter's configuration.

## Changing them

The dashboards are generated by `generate_dashboards.py`. Edit it rather than the JSON, then
regenerate them and run the tests, from the repository root:

```sh
python3 otel-dashboards/generate_dashboards.py
go test ./otel-dashboards/
```

## Tests

`go test ./otel-dashboards/` runs without a server. It checks the dashboards' conventions (the
datasource and schema variables, multi-value variables with `*` for *All*, tables read from
`$schema`, variables passed as `${name:json}`, time series panels in the time series format) and that
the JSON is what the generator writes.

`TestDashboardsLive` runs each dashboard query against a Kinetica server, through the plugin's own
backend, the way Grafana sends it. It creates a schema with the exporter's metric tables, loads the
metrics of `testdata/metrics.sql`, whose results are known, and checks the values of every panel at
*All*, of some panels with filters, and of every variable. The schema is dropped at the end; set
`KINETICA_TEST_KEEP_SCHEMA` to keep it and look at the metrics through the dashboards.

```sh
KINETICA_TEST_URL=http://127.0.0.1:9191 KINETICA_TEST_USER=... KINETICA_TEST_PASSWORD=... \
  go test -count=1 -v -run TestDashboardsLive ./otel-dashboards/
```

`testdata/metrics.sql` creates the metric tables with the statements of the exporter's
`sql/datamodel.sql`. When the exporter changes its tables, change them here too.
